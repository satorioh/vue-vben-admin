# 关键字标注功能设计

## 目标

在现有 OCR 识别、定位框、拖选和复制能力之上，增加关键字搜索、全部高亮和匹配结果导航。OCR 接口及现有交互保持不变。

## 界面与交互

在 `preview-container` 上方增加单行 `keyword-labeling-toolbar`，依次包含关键字输入框、“标注”按钮、结果数量、“上一处”和“下一处”按钮。

用户点击“标注”后执行字面量精确匹配并展示全部结果。当前结果带额外轮廓以区别于其他黄色高亮；页面滚动到当前结果。上一处和下一处在结果首尾循环。无匹配结果时显示 0 并禁用导航。

上传新文件、重新识别、清空关键字或 OCR 数据被清除时，同时清除匹配结果和高亮。未完成 OCR 识别时执行标注不会报错，结果保持为 0。

## 数据模型与匹配

新增 `keywordData`，包含串联后的完整 OCR 文本和字符映射。每个字符映射记录：

- 原 OCR `locations` 条目的索引；
- 字符在该条目文本中的偏移；
- 字符对应的原始坐标。

匹配使用完整文本上的 `indexOf` 搜索，并将搜索起点每次前移一个字符，从而支持重叠结果。每个命中区间通过字符映射还原为可高亮的坐标片段。

大多数中文 OCR 条目只有一个字符，可直接使用原坐标。如果单个条目包含多个字符但没有字符级坐标，则按字符数等分该条目的宽度，近似计算每个字符的水平范围。连续命中同一条目中的字符可合并为一个高亮片段。

## 渲染与导航

保留现有 `.ocr-text` 元素及拖选逻辑，避免影响边框开关和复制功能。关键字命中使用独立的绝对定位覆盖层，并沿用当前预览宽高比例换算。窗口或预览尺寸变化时，现有重排流程同时重新计算高亮。

每个匹配结果的第一个高亮片段作为导航锚点。导航时更新当前结果索引，并对锚点调用平滑 `scrollIntoView`。

## 验证

将文本串联、字符映射和重叠匹配实现为可独立验证的纯函数，覆盖单字符条目、多字符条目、跨条目匹配、重叠匹配和无结果场景。页面修改完成后运行 ESLint、`pnpm type:check` 和 `pnpm build`，并手动验证识别、拖选复制、边框显示、高亮、缩放重排和循环导航互不冲突。
