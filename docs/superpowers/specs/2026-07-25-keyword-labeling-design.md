# 关键字标注功能设计

## 目标

在现有 OCR 识别、定位框、拖选和复制能力之上，增加关键字搜索、全部高亮和匹配结果导航。OCR 接口及现有交互保持不变。

## 界面与交互

在 `preview-container` 上方增加单行 `keyword-labeling-toolbar`，依次包含关键字输入框、“标注”按钮、结果数量、“上一处”和“下一处”按钮。

用户点击“标注”后执行字面量精确匹配并展示全部结果。命中的 OCR 文字元素使用半透明红色背景。页面滚动到当前结果；上一处和下一处在结果首尾循环。无匹配结果时显示 0 并禁用导航。

上传新文件、重新识别、清空关键字或 OCR 数据被清除时，同时清除匹配结果和高亮。未完成 OCR 识别时执行标注不会报错，结果保持为 0。

## 数据模型与匹配

新增 `keywordData`，包含串联后的完整 OCR 文本和字符映射。每个字符映射记录：

- 原 OCR `locations` 条目的索引；
- 字符在该条目文本中的偏移；

匹配按字符遍历完整文本，并将搜索起点每次前移一个字符，从而支持重叠结果。每个命中区间通过字符映射还原为对应的 OCR 条目索引。

如果关键字只命中多字符 OCR 条目的一部分，仍高亮该条目对应的整个 `.ocr-text` 元素，不再拆分字符宽度。

## 渲染与导航

不创建额外高亮展示层。生成 `.ocr-text` 元素时写入 OCR 条目索引；匹配后直接给对应元素添加高亮类，背景色为 `rgba(255, 0, 0, 0.5)`。清空匹配或重新生成 OCR 元素时同步移除并重新应用高亮类。

每个匹配结果的第一个 `.ocr-text` 元素作为导航锚点。导航时更新当前结果索引，并对锚点调用平滑 `scrollIntoView`。当前结果不使用额外轮廓或特殊颜色。

## 验证

将文本串联、字符映射、重叠匹配和命中 OCR 索引去重实现为可独立验证的纯函数，覆盖单字符条目、多字符条目、跨条目匹配、重叠匹配和无结果场景。页面修改完成后运行测试、ESLint、类型检查和生产构建，并手动验证识别、拖选复制、边框显示、红色背景、重排和循环导航互不冲突。
